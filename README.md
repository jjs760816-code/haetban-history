# 햇반, 역사를 짓다

**카드를 모으고, 나라를 세우고, 시대를 열다.**

2026 · 5학년 9반 역사 체험 프로젝트. 실물 카드로 진행한 활동을 공용 서버에 기록합니다.

## 시작 방법

1. 교사가 **학급 만들기**에서 학급 이름과 8자 이상의 교사 비밀번호를 정합니다.
2. 교사 관리에서 8자리 접속 코드 또는 학생 링크를 공유합니다.
3. 학생은 **처음 참여**에서 코드 확인 후 실제 이름·학생 번호·6자 이상의 개인 비밀번호·지역·직업으로 등록합니다.
4. 이후에는 **학생 로그인**, 교사는 **교사 로그인**으로 접속합니다. 접속 코드와 비밀번호를 보관하세요.
5. 학생이 실물 카드·활동을 기록하면 교사가 확인하고 승인합니다.

## 구현 기능

- 개인 자원·역사·유물 카드, 카드별 도장 수와 온
- 지역 특화 자원과 개인 직업 자원의 별도 발행 요청
- 교사 승인 후 공식 보유량·국력 반영
- 거래 상대 확인 → 교사 승인 → 양쪽 자산 동시 갱신
- 카드 소유권을 이전하지 않는 후보 지지
- 후보 자격과 지지 점수에 따른 지도자 선출, 동점 보류
- 국가 건설·고려·조선·일제강점기 전환과 시대별 명칭·직업·지도자 변화
- 지도와 지역별 순위, 자원 창고, 성장 연대기
- 교사 수량·온 정정, 소속·직업 변경, JSON 기록 내려받기
- 비밀번호 PBKDF2 해시, 만료되는 서버 세션, 역할별 쓰기 권한
- 낙관적 잠금(version 비교 갱신)과 충돌 재시도로 동시 기록 보존

## 화폐와 공동체

2학기 화폐는 **온(溫)**. 따뜻할 온에서 가져왔으며, 서로의 노력과 도움을 잇는 교환 수단입니다. 돈의 많고 적음이 학생의 가치나 지도자 자격을 뜻하지 않습니다. 학생은 온으로 카드를 교역하고 함께 성장합니다.

## 게임 규칙

지역·직업별 자원, 왕 선출 방식, 지도 경계는 수업용 규칙입니다. 지도는 한반도 위치를 단순화한 개념도이며 실제 행정구역이나 시대별 영토가 아닙니다.

- 자원 1장 = 1점
- 역사·유물 = (카드 시대 기본 가치 + 도장 수 × 도장 가치) × 수량
- 기본 가치: 구석기 1 / 신석기 2 / 국가 건설 3 / 고려 4 / 조선 5 / 일제강점기 6
- 온은 거래 수단이며 국력·지지 점수에서 제외
- 지역 합계는 그 지역 학생의 자산 합계. 같은 카드를 개인과 지역에 이중 합산하지 않음
- 기본 후보 조건은 인구 2장·역사 1장·가치 10점이며 교사가 변경 가능
- 시대 전환은 카드·온·직업의 자원 종류를 보존하고 지역·직업 이름을 변경. 지지와 지도자는 초기화하며 미처리 요청은 종료
- 지역 발행 조건의 점수·분배는 교사가 요청 사유를 확인하여 승인하는 방식. 자동 점수 통장과 모둠장 전용 분배 기능은 후속 범위
- 기록 내려받기는 백업·열람용이며 자동 복원 기능은 아직 없음
- 교사·학생 비밀번호 분실 시 자동 복구 기능은 아직 없음
- 이전 시대 스냅샷 최근 20개, 활동 연대기 최근 500건 보관. 중요한 시점에는 JSON으로 내려받기

## 구성과 실행

`app/page.tsx`: 학생·교사 UI / `app/api/game/route.ts`: 인증·서버 API / `lib/game.ts`: 게임 규칙 / `db/schema.ts`, `drizzle/`: D1 스키마·마이그레이션

이 저장소의 실행 본체는 Vinext/Cloudflare Worker입니다. GitHub Pages만으로 API와 DB가 실행되지는 않습니다. 소스 변경 시 서버 서비스도 별도로 재배포해야 합니다. Pages 입구 갱신과 서버 배포는 자동 연결되어 있지 않습니다.

로컬 실행은 Node 22.13 이상에서 `npm install` 후 `npm run dev`를 사용합니다. D1 사용 전 `npm run build` 후 starter README의 로컬 마이그레이션 명령으로 `drizzle/0000_warm_zarda.sql`을 적용하세요. `pnpm-lock.yaml`을 제공하며 지원 환경에서는 pnpm을 사용할 수 있습니다.

## 향후 역사 게임 연동

모든 방·학생·카드·요청에 고유 ID를 사용하며 `schemaVersion: 1` 형식으로 기록합니다. 지지 관계는 카드 소유권과 분리됩니다. 현재 `/api/game`은 이 앱의 세션으로 인증하는 내부 API입니다. 외부 게임용 보상 API·연동 키·웹훅은 아직 열려 있지 않습니다.

후속 연동은 **게임 결과 이벤트 ID → 중복 검사 → 보상 요청 → 교사 승인 → 카드 반영** 구조를 권장합니다. 외부 게임에 교사 비밀번호나 관리자 세션을 전달하지 않습니다. 자세한 내용은 `INTEGRATION.md`를 참고하세요.

## 태블릿·동시 기록 재점검

학생 로그인은 실명 + 학생 번호 + 개인 비밀번호를 사용합니다. 동명이인은 서로 다른 학생 번호로 분리됩니다. 첫 학생 접속에는 사용 방법 팝업을 표시하며 ‘사용 방법’ 버튼으로 다시 열 수 있습니다. 주요 입력칸·버튼은 44 CSS px 이상으로 구성합니다.

25개의 독립 학생 세션으로 서버 동시 등록·카드 제출·교사 승인을 재검증했고, 카드 50장이 누락 없이 보존됐습니다. 같은 요청을 동시에 다시 전송해도 1건만 접수하도록 requestId 중복 방지를 추가했습니다. 이름·번호 불일치 로그인 거부 및 동명이인 계정 분리도 확인했습니다.

실제 갤럭시 탭 하드웨어·삼성 인터넷 엔진 테스트와 브라우저 화면 크기를 맞춘 검증은 다릅니다. 태블릿 화면 검증 결과는 후속 점검 기록을 참고하세요.
